# Markdown 完整性与 MCP 执行可靠性

## 基线与架构决策

来源：Obsidian NotEMD 1.9.12，提交 `0f493b8d3cd60553e5a517660ca1a729ce4acdfc`。目标拥有 Python/FastAPI 处理后端和 Node stdio 桥接。图表端点返回 Mermaid 文本，没有可直接迁入的 Drawnix 布局、SVG/PDF 渲染器或诊断弹窗。

值得迁移的是保守规范化、异步取消/重试行为和完整诊断可见性的契约。部分旧源工具仍删除标点或取消金额转义，整体翻译这些实现会复制缺陷。

## 实现组件与根因

| 归属 | 原故障 | 更新后的行为 |
| --- | --- | --- |
| `markdown_processing.py` | 全局删除引号、按最后箭头猜测围栏结束、删除内部代码围栏、改动转义美元符 | 统一所有权扫描，仅移除完整外层包装，保留标签/未来类型/代码/金额/换行，有限修正错误语言标签 |
| `notemd_core.py` 重试 | `time.sleep` 阻塞事件循环，永久配置错误反复重试，取消检查不一致 | 异步退避，仅重试暂态 HTTP/传输故障，传播执行前取消与原生任务取消 |
| 批量写入 | 直接覆盖并规范换行 | 严格 UTF-8 读取，精确文本比较，同目录暂存/fsync/重新读取/替换，跳过符号链接，明确报告只读错误，无变化不写入 |
| `process-output.js`、`cli.js` | 子进程日志混入协议 stdout，协议错误码被统一覆盖 | 人读日志写 stderr，stdout 专用于协议，保留 MethodNotFound，桥接错误脱敏，导入 CLI 不自动启动 |
| 后端启动 | 默认绑定所有网卡，健康检查可能命中其他服务 | 桥接绑定本机并核对每子进程标识，直接 HTTP 入口提供显式主机/端口环境变量 |
| 打包/测试 | wheel 缺少模块、控制台入口错误、测试模拟生产且删除固定目录 | 显式 py_modules 与真实入口，npm 白名单包含新模块，生产模块测试使用临时夹具 |

最终复核在同系列技能项目复现了标签修复的保真问题，并在此同步增加缩进代码保护；还发现 Google 密钥进入请求 URL、Windows 只读文件留下暂存文件，以及符号链接入口无法启动。现改用受支持的密钥请求头，在暂存前拒绝只读输入，并按入口真实路径判断 CLI 启动。

干净 CI 还发现 selectolax 1.0 已移除废弃的 Modest 解析器。研究功能现改用受支持的 Lexbor 后端，依赖范围覆盖兼容的 0.3.x 至 1.x，并增加搜索结果及正文提取的生产函数回归测试。

## 兼容性

HTTP 路由、MCP 工具名称/别名和既有响应字段保持稳定。公开 `cancelled` 布尔值表示执行前取消，不是实时取消令牌。Python 原生任务取消有效，但 SDK 请求取消尚未通过 HTTP 桥接接通。

支持基线为 Python >=3.10、Node >=22.19。CLI 桥接仍使用 8000 端口；直接 HTTP 运行可设置 `NOTEMD_HOST`、`NOTEMD_PORT`，对外开放需要部署层鉴权。使用方应把 stdout 作为协议通道，从 stderr 收集诊断。

语法清理不实现 Mermaid 解析器。不支持的语法保留原文，不宣称可以渲染。本次没有 PDF 导出或 UI 折叠能力。换行/BOM 保留约束适用于工具拥有的修复操作，不代表所有模型生成响应逐字节不变。

## 后续适合迁移的组件

1. 将 MCP 请求取消经 HTTP 连接到后端任务生命周期，并处理 stdin EOF 时的子进程退出。
2. 把重命名/删除的反向链接更新改为完整事务操作，建立仓库目录边界并明确报告部分失败。这些历史路径不属于本次语法修复范围。
3. 渲染产物应通过具名能力边界引入，验证 MIME/输出、渲染器版本及溯源；浏览器 CSS/PDF 内部实现不应放进文本后端。
4. 后续扩展提供商时，再根据需要从较大的 core 模块提取传输职责，当前不增加单纯转发的服务层。

暂存替换能在提交前检测源文件变化，但不是阻止外部写入方竞争的文件系统比较交换锁。未宣称已解决无限提供商响应、端到端授权或全部旧文件修改路径。

## 验证与交付

- `npm test`：4 项通过，覆盖工具路由兼容、协议错误、子进程日志隔离、敏感响应排除和 npm 风格符号链接入口。
- `npm run test:python`：14 项通过，覆盖生产处理、Markdown 保护、暂态重试、非阻塞取消、写入失败/只读清理、Google 密钥传输、HTML 研究提取和配置日志脱敏。
- 新增边界回归在修复前失败，修复后通过。
- wheel 构建后在仓库外隔离安装，四个模块与控制台入口均从安装产物解析。
- npm 包包含两个新增运行时模块；源码分发清单包含 requirements。
- CI 在 Linux/Python 3.10、Windows/Python 3.13 与 Node 22.19 上验证测试及两种打包形式。
- 未使用真实提供商、翻译 API、LM Studio 或 GUI。文档翻译均由主助手直接编写。

实现与本地验收完成。版本仍为 0.6.1：这是注册表版本之后的源码更新，没有覆盖或新发布 npm/PyPI 包。
